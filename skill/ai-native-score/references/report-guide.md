# 可读报告约定

先写本次能负责的结论，再给覆盖与遗漏、真实强项、优先改进、定性六维、2–3个具体行动与验证方式，最后附证据。不要用扫描量、时间、工具名或术语堆砌代替结论。

每项指标说明：适用行为锚点；人类实际决策或行动；agent做了什么；可回链的结果和后续独立验证；为何该级、为何不足下一级；反证及替代解释；不确定性；下一项行动及如何验证。单纯要求agent验证，不证明验证已发生。人类明确作出的委派/选择是相关指标的行为证据，但仍需执行与核验才能完整评分。agent自己犯错不直接扣用户分。

证据条目保留本地locator、日期、工具/实例、任务谱系、actor、类型、事实和验证状态。actor允许human、agent、thirdparty、unknown；类型允许intent、action、artifact、verifiedoutcome、unknown。适配器导入的类型只是材料声明，verification始终unverified；评估中的引用链和核验解释负责说明如何使用它。未知作者或无法核验的导出不能假装第三方认证。支持范围、反证与验证方法在对应决策中列出。

缺少任何指标或只有低质量证据时，不显示临时总分、六维分、分数区间或雷达，不生成public-score文件。缺连接、未适配、被拒读是覆盖缺口，不是能力缺陷。不要用重复示例制造稳定性；同一任务续接、重复回放、跨工具拷贝合并为同一taskGroups。

数值通过评分门槛时，每个数值必须回链到该指标的完整行为链。未解决的冲突保留原反证并将该项置未知；不能只选好看的证据。4级也要说明扩展到下一场景所需证据，不能宣称能力已完美。

新读者检查：只给读者报告，不给生成过程，询问“是否评分、依据哪些工具和日期、哪些来源没读、哪些结论可能不成立、最先做什么、如何验证”。若读者把未读取当低能力，或把请求当结果，修改报告并重读。测试只用合成材料，用户真实记录不进入代码仓库。

本模板和措辞由本项目原创。报告流程在开发时私有使用Anthropic官方doc-coauthoring的上下文整理、迭代及新读者检验思路；未复制其skill原文或将其再许可。没有运行Notion或复制Proprietary报告插件。

审阅就绪还需review清单：reviewedEvidence逐事件列明已读ID，excludedEvidence列明排除ID及原因，两者不得重叠或遗漏。taskFamiliesFinalized和counterexampleSearchComplete必须为true才可计分；排除材料不能支撑评分。来源无法读取不是能力失败，但不能据此声称全历史覆盖。

同一事件可以支持多个相关指标；必须在全部已审材料中寻找正反证据，不能因为没有把ID放进某项support就声称证据不存在。合成报告不预设目标总分；独立公式回归与行为锚点评估分开。
