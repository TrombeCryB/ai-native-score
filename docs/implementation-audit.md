# am-0.2 改造审计

本次仅审计项目源码、公开方法和合成测试，未打开个人评估原始记录，也未复核或改动任何个人得分。“五维75”的实际个案无法在此任务核实；代码并不存在默认填3。已确认的机制风险是旧评估器只检查support中含人类消息和任务数，因此多次提出要求可被误判为3级稳定实践。旧合成fixture本身也曾展示该风险。am-0.2使用明确行为链替换这个门槛，保留0–4原有六轴24项，不为视觉整齐填充75。

| 要求 | 具体实现与验收 |
| --- | --- |
| 评分失真 | 每项0–4行为锚点；人类决策/行动→结果→后续核验；独立任务谱系；反证/不确定性/下一级差距；低质量或未解决冲突未知 |
| 先发现与安全 | discover只查已知或提供的根目录元数据；不读配置/凭据；受限及symlink拒读；明确非绝对安全 |
| 缺证据不出数值 | summarize全部维度/总分/区间置null；radar空；evaluate不写public-score；export/publish拒绝；HTML定性报告 |
| 工具广度 | Codex、Hermes多profile原生；其他列明未适配、需导出；统一normalized-export及显式根目录扩展，无虚假原生支持 |
| 来源覆盖 | 工具/实例/日期/读取状态/文件/记录/任务/遗漏/排除；数量不加分，未连接不扣分 |
| 视觉和公开边界 | 离线深绿网格像素报告；公共源码只有skill和所需收集/评估/报告模板及测试；Worker源码/部署私有 |
| 可读及提升 | 结论先行、2–3行动和验证、指标理由/反例/局限、本地证据附录；原创综合与公开标准映射边界明确 |
| 时间和进度 | CLI启动阶段说明、固定预算与截断披露；agent按覆盖量报告进度；耗时不作为可信度 |

安全回归只使用合成fixture和临时目录，未对用户个人评估运行收集器。评分门槛能校验引用、角色、任务、顺序及最低证据要求，不能证明模型对文本的语义判断正确，也不能阻止伪造账本；需要新读者检验和用户复核。评价是实验性原创综合而非经过效度验证的测量。

am-0.2标识本轮证据协议与评分就绪门槛，六轴、24项和等权公式保持不变；不拿新版协议自动重评旧个人记录。独立新读者检验实际发现并推动修复：通用证据不足、等级差距错配、跨指标遗漏、来源数量不一致。最终示例仅一个常规任务家族及72个合成事件，不预设目标总分；67仅用于独立数学回归。
